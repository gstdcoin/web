# GSTD Token Site - Low Resource VPS Setup

## Оптимизация для VPS с ограниченными ресурсами (1 CPU, 1GB RAM)

### 🚀 Быстрый запуск

```bash
# Запуск оптимизированной версии
./start-optimized.sh

# Запуск с очисткой кеша
./start-optimized.sh --clean

# Мониторинг ресурсов
./monitor-resources.sh

# Мониторинг в реальном времени
./monitor-resources.sh --watch
```

### 📊 Распределение ресурсов

- **Next.js приложение**: 400MB RAM, 0.8 CPU
- **Caddy (веб-сервер)**: 100MB RAM, 0.2 CPU
- **Система**: ~500MB RAM, 0.2 CPU

### 🔧 Оптимизации

#### Next.js конфигурация
- Ограничение памяти: `--max-old-space-size=256`
- Оптимизация сборки: `memoryBasedWorkersCount: true`
- Минимизация изображений: только WebP формат
- Отключение телеметрии

#### Docker оптимизация
- Многоэтапная сборка для минимизации размера
- Alpine Linux для минимального размера образа
- Ограничения ресурсов на уровне контейнера
- Read-only файловая система для безопасности

#### Системные оптимизации
- Ограничение логов (5MB максимум)
- Оптимизированные health checks
- Безопасные настройки контейнеров

### 🛠️ Команды управления

```bash
# Запуск
./start-optimized.sh

# Остановка
docker-compose down

# Перезапуск с очисткой
./start-optimized.sh --clean

# Просмотр логов
docker-compose logs -f

# Мониторинг ресурсов
./monitor-resources.sh --watch
```

### 📈 Мониторинг

Скрипт `monitor-resources.sh` отслеживает:
- Использование памяти
- Загрузку CPU
- Использование диска
- Сетевые соединения
- Состояние приложения

### ⚠️ Важные замечания

1. **Память**: Приложение ограничено 400MB RAM
2. **CPU**: Используется до 80% одного ядра
3. **Диск**: Логи ограничены 5MB
4. **Безопасность**: Контейнеры работают в read-only режиме

### 🔍 Устранение неполадок

#### Если приложение не запускается:
```bash
# Очистка кеша
./start-optimized.sh --clean

# Проверка ресурсов
./monitor-resources.sh

# Просмотр логов
docker-compose logs web
```

#### Если не хватает памяти:
```bash
# Уменьшение лимитов в docker-compose.yml
# Изменение memory: 400M на memory: 300M
```

#### Если медленно работает:
```bash
# Проверка загрузки CPU
top

# Оптимизация через мониторинг
./monitor-resources.sh --watch
```

### 📝 Переменные окружения

Файл `.env.production` содержит:
- `NODE_OPTIONS`: Ограничения памяти Node.js
- `NEXT_TELEMETRY_DISABLED=1`: Отключение телеметрии
- `NODE_ENV=production`: Продакшен режим

### 🎯 Рекомендации

1. Регулярно мониторьте ресурсы
2. Очищайте кеш при проблемах
3. Используйте логи для диагностики
4. Обновляйте зависимости осторожно
5. Тестируйте изменения на staging

### 📞 Поддержка

При проблемах проверьте:
1. Логи: `docker-compose logs -f`
2. Ресурсы: `./monitor-resources.sh`
3. Статус: `docker-compose ps`
4. Перезапуск: `./start-optimized.sh --clean`
